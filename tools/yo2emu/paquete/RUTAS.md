# Server paths in package mode

Contract between the server (`tools/yo2emu`) and whoever builds the package (first-start extractor, `duelcore.mjs`,
launcher). Every path comes from **a single module**: `yo2srv/rutas.py`. Without any of these variables (development
mode, or an existing server run from a checkout) everything behaves as it always has.

## Variables

| Variable | What it is | Without it | In the package |
|---|---|---|---|
| `YO2_PAQUETE` | `1` = package mode (see below) | off | `1` |
| `YO2_JUEGO_DATOS` | root of the game data = the `data\` folder of the 2008 client's `merge.dat`: each `data\…` entry WITHOUT the leading `data\` (what `paquete/extraer_juego.py` writes) | `<repo>/_original/extracted/merge2008/data` | the folder generated by the extractor |
| `YO2_VENDOR` | `cards.cdb`, `strings.conf`, `CardScripts/` (ProjectIgnis) | `<repo>/_vendor` | the package's `_vendor` |
| `YO2_NODE` | `node.exe` (≥ 22.13: `node:sqlite`) | the `node` on the PATH | the package's `node.exe` |
| `YO2_DUELCORE` | the engine. A `.mjs`/`.js` is launched with `node <mjs>` (cwd = its folder); a `.mts`, with tsx as in development | `tools/yo2emu/duelcore/duelcore.mts` (+ tsx from `apps/server/node_modules`) | `duelcore.mjs` (esbuild, a single file) |
| `YO2_STATE` | `state.json` (and the `.sqlite` next to it; also `admin_*.json`, `admin_eventos/`, `repeticiones/`) | `tools/yo2emu/state.json` | by default `%LOCALAPPDATA%\YO2Online\servidor\<5730+offset>\state.json` |
| `YO2_LOGDIR` | log folder | `tools/yo2emu/logs` (`logs/prueba` with an offset) | by default `%LOCALAPPDATA%\YO2Online\servidor\<5730+offset>\logs` |
| `YO2_LOG_MAX_MB` / `YO2_LOG_KEEP` / `YO2_LOG_KEEP_OCG` | cap per log file, logs kept, engine traces kept | `0` = no cap | `20` MB / `10` / `200` |

`duelcore.py` passes `VENDOR_DIR` (the variable read by `apps/server/src/duel/data.ts`) = `YO2_VENDOR` when it is set,
and also with a `.mjs` (the relative computation in `data.ts` no longer works outside `apps/server/src/duel`). With tsx
and without `YO2_VENDOR`, it does not touch it.

## What the server reads from `YO2_JUEGO_DATOS`

Measured with a Python audit hook on `open`/`scandir` in a test instance with NPC and PvP duels, shop, packs and the
post-PvP card, and reviewed in the code. Paths relative to the root, EXACT names from `merge.dat` (without its leading
`data\`):

**Required files** (`rutas.JUEGO_FICHEROS`; in package mode the server does not start without them):

| File | Used by | For |
|---|---|---|
| `bin#/card_prop.bin` | `research/traductor/cardmap.py` (via `tools/build_cards.py`) | YO2 id -> internal id of each card |
| `bin#/card_name_e.bin` | cardmap | English name (match with `cards.cdb`) |
| `bin#/card_indx_e.bin` | cardmap | index of those names |
| `common/yo2pbinmap.dat` | `research/avatar/proposal.py`, `research/persistencia/proposal.py` | PBIN bits (clothes, titles) |
| `cardpack/packinfo_s.txt` | `yo2srv/tienda/tienda.py` (`PACKINFO`), `research/persistencia/duelpass.py` | catalogue of shop packs |

**Folder whose files are read depending on what the game asks for** (`rutas.JUEGO_CARPETAS`):

| Folder | Files | Used by |
|---|---|---|
| `cardpack/` | `<id>.iid` (cards in a pack) and `<id>.ydc` (structure decks): the 78 `.iid` and 86 `.ydc` of `merge.dat` | `tienda.shop_purchase`, `persistencia.pack_file` / `structure_deck_cards`, `duelpass` |

From `cardpack/` the server does not read the `.png` (15.0 MB), the `.bin` (0.26 MB) or the `.txt` except
`packinfo_s.txt`. Everything it reads from `YO2_JUEGO_DATOS` adds up to ≈ 0.26 MB (219 KB from the 5 files + 42 KB of
`.iid`/`.ydc`).

**Outside `YO2_JUEGO_DATOS`, and not needed in the package:**

- `_original/extracted/merge/data/cardpack/` (previous client): `persistencia.pack_file` looks there if a file is not
  in merge2008; there is currently no file that exists only there (verified), so it changes nothing.
- `_original/yo2_2008-11/profiles/<name>/deck.ydc`: only with `YO2_TRUNK_START=deck`. The package uses `all3` (the
  default in `yo2srv/arranque.py`: everyone starts at Lv1 with every card ×3).
- `_original/ghidra/protocol.json` and `avatar/npc/*.csv`: only the self-tests (`--test`/`selftest`) of
  research/lobby, lockstep, duelfin, persistencia and avatar.
- `avatar/wu/*_data.csv` and the images: only an admin tool (not included), which is not part of the public package.

## What it reads from `YO2_VENDOR`

- `cards.cdb`: cardmap (`build_cards.CDB`), `research/ia/brain.py` (`CardDB`) and duelcore (`data.ts`).
- `strings.conf`: duelcore (`strings.ts`).
- The whole `CardScripts/`: duelcore (every `.lua`, an index of the entire folder) and `translator.py` (`SCRIPTS_DIR`:
  `constant.lua` and the `.lua` of the cards in the duel; it walks the folder).

## Tables derived from the client (generated by `paquete/generar_tablas.py` on the host's PC)

`research/ia/cards_yo2.csv`, `research/ia/npc_decks.json`, `research/ia/npc_profiles.json`,
`research/persistencia/valid_cards.json` and `research/persistencia/titles.json` (`rutas.TABLAS_GENERADAS`). Neither
the zip nor the source repository contains them. `primer_arranque.py` rebuilds them on every "Host a server"
(idempotent), and in package mode the server does not start without them (exit code 3).

## What ships with the code (not game data)

`auto_replies.json`, `research/lobby/auto_overrides.json`, `npc_ids.json` (without dialogue),
`research/cuentas/logseguro.py`, `www/` (HTTP 8730) and `tools/build_cards.py` (cardmap imports it: `norm`, `RENAMES`,
`utf16_table`; **Pillow is no longer needed**, only `build_cards.main()` imports it).

## Package mode (`YO2_PAQUETE=1`)

- **No client**: `yo2.exe` is not launched (like `YO2_NO_CLIENT=1`; `YO2_NO_CLIENT=0` launches it again). `frida` is
  never imported at startup (not even in development): only `yo2srv/cliente.py` imports it, when launching the client.
- **State and logs** in `%LOCALAPPDATA%\YO2Online\servidor\<5730+offset>\` (unless `YO2_STATE`/`YO2_LOGDIR` are set).
  One server per port; the flag profile does not change the folder (accounts do not depend on it).
- **No root-profile account**: `OWNER_ACCT` = `None` unless `YO2_OWNER_ACCT` is set. Nobody inherits the profile at the root
  of `state.json`; every account goes to `state["accounts"]` and starts at Lv1 with every card ×3
  (`YO2_TRUNK_START=all3`, already the default).
- **Stops if something is missing** (`yo2srv/paquete.py`, message in English, to stderr and to the log): a file from
  the list above, `cards.cdb`, `strings.conf`, `CardScripts/`, the engine or node (exit code 3), or if the rules engine
  (`ocg_duel`: duelcore + CardMap) does not start (exit code 4). This happens before any port is opened. In
  development, `[ocg] ocg_duel.py no cargado` is still just a log line.
- **Capped logs**: 20 MB per file (when it is exceeded, a new `YYYYMMDD-HHMMSS.log` in the same folder; `log_path` in
  the namespace is updated), the 10 most recent logs and the 200 most recent engine traces are kept (`logs/ocg`; a
  trace stops growing at 20 MB). Only files with those names in those folders are deleted.

In both modes, `run.py` deletes its `%LOCALAPPDATA%\YO2Online\consola_<port>.txt` on exit (normal exit, `DEADLINE = 1`
from the console, Ctrl+C), only if it wrote that file itself.

## Notes

- The admin tool (not included) starts if its files are present (`YO2_ADMIN_PANEL=0` turns it off). Without its files
  the log only shows "panel web no arrancado".
- `storage/` uses `sqlcipher3` if it is installed and plain SQLite (stdlib) otherwise: the package ships without
  encryption.
